# ShortX 脚本：挥手控制抖音切换视频 · 使用指南

> 手掌在手机顶部（听筒旁距离传感器）上方挥过或遮挡 → 抖音自动滑到**下一个视频**。
> 完全无接触，湿手、戴手套、满手泡沫都能用。原理：ShortX 监听距离传感器 → 触发后用 root 权限执行 `input swipe` 系统级滑动命令。

> **想改用语音？** 说「下一个」就翻页——见同目录的《语音切抖音-使用指南.md》和 `语音切抖音-v3.9.apk`，装上即用（v3.1 起不使用 root，默认走「通知触发」：App 发一条含魔法串的通知，ShortX 收到即执行翻页；后台也能用，不受 ColorOS 后台弹窗拦截影响）。也有无语音版 `抖音手势控制-无语音版-v2.1.apk`（挥手/摇一摇/耳机键触发，同样默认通知触发）。

## 一、前提条件（缺一不可）

| 条件 | 说明 |
|---|---|
| ShortX 已激活 | Xposed/LSPosed 中启用 ShortX 模块并勾选作用域 |
| Root 已授权给 ShortX | Magisk 等弹窗点「允许」；动作靠 `su -c input swipe` 注入滑动 |
| 屏幕亮着 + 已解锁 | 滑动命令只能作用在前台界面；密码锁屏无解，建议洗碗时段用无锁/滑动解锁 |
| 抖音在前台 | 打开抖音推荐页再开始 |
| 手机**立着放** | 支架或靠在水槽立面，让屏幕顶部（听筒/传感器）朝向你的手 |

## 三、导入方法（三选一）

**A. 文件导入**：把 `.txt` 文件传到手机 → ShortX 首页右下角 **+** → **文件导入** → 选择文件。

**B. 剪贴板导入**：用任意方式复制 `.txt` 全文 → ShortX → **+** → **剪贴板导入**。

**C. 手动搭建（最稳，5 分钟）**——如果导入后触发器显示异常，按此步骤重建：

1. ShortX 首页右下角 **+** → 新建**自动指令**，标题填「抖音挥手切换」
2. **添加触发器** → 搜索「**距离**」或「传感器」→ 选距离传感器 → 触发方式选「**靠近/遮挡**」(near)
3. **添加条件**（可选）→ 选「屏幕开启」
4. **添加动作** → 搜索「**Shell**」→ Shell 命令：
   - 命令填：`su -c "input swipe 707 2100 707 1282 120 && sleep 0.8"`
   - 勾选 `singleShot`
5. （可选）再加一个动作「振动」80ms —— 挥完手震一下，确认触发了
6. 保存，打开规则开关

## 三之二、被其他 App 触发（两种触发方式 · 语音切抖音 v3.1 起默认「通知触发」）

调用方 App（《语音切抖音》v3.1 / 《抖音手势控制》无语音版 v2.1）识别到口令/硬件事件后，有两条通道让 ShortX 执行翻页——**执行环节（root 注入）全部在 ShortX 里完成，调用方不需要 root、也不需要无障碍服务**：

**通道一：通知触发（v3.1/v2.1 默认，推荐）**

调用方触发后发一条内容为魔法串 `HF_CMD_NEXT`（下一个）或 `HF_CMD_PREV`（上一个）的通知（静默通道、1.5 秒自动消失），
ShortX 的「有新通知」规则按**调用方包名 + 内容匹配**收到即执行。
这是**系统级钩子**——后台 App 发通知永远被系统允许，**不需要后台弹出界面、不需要悬浮窗权限**，完美绕开 ColorOS 对后台拉起 Activity 的拦截。

配套规则文件：`ShortX-抖音通知触发-下一个.txt` / `ShortX-抖音通知触发-上一个.txt`（导入即用；重新导入会变 id，但通知触发靠包名+内容匹配，**不受 id 变化影响**）。

**通道二：DeepLink 触发（v2.7~v3.0/v2.0 的默认用法，v3.1/v2.1 保留为备选）**

每条规则都有唯一的运行链接，形如 `shortx://run?id=DA-1d634d7d-da36-49b8-a588-b3c3d00be499`。
调用方识别到口令后直接拉起这个链接，ShortX 就会执行对应规则。
本目录原有的 `ShortX-抖音挥手切换.txt` / `ShortX-抖音摇一摇切换.txt` / `ShortX-抖音音量键切换.txt` 三条规则都带 DeepLink id，可直接用于通道二。

- 获取链接：在 ShortX 里对该规则选「运行/分享」之类入口，复制 `shortx://run?id=...`
- **重新导入规则后 id 会变**，调用方（App 首页的 DeepLink 输入框）要同步更新
- 调用方从后台拉起链接时，ColorOS 可能按「后台弹出界面」策略拦截——v3.1/v2.1 已用悬浮窗辅助启动缓解（需悬浮窗权限）；仍不行就改用通道一
- 规则本身需保持开关打开；屏幕开启条件满足时才会执行

## 四、坐标已按你的手机配好（一加 Ace 5 至尊版 · 1272×2800 竖屏）

三个规则文件里的命令已直接写成 **`input swipe 707 2100 707 1282 120 && sleep 0.8`**，导入即用，无需再改。

> **v3 重要修正（2026-10-24）**：v2 版误把一加 Ace 5 至尊版的规格书写法「2800×1272」当成「宽×高」，算出 x=1556，而你的手机实际是 **1272×2800 竖屏**（宽 1272）。x=1556 **超出屏宽**，`input` 事件被系统直接丢弃——这就是「命令执行成功、抖音却毫无反应」的原因。现已改为按竖屏口径计算：x=707（55.6% × 1272），y1=2100（75% × 2800），y2=1282（45.8% × 2800），时长 120ms。**用 v2 规则没反应的，请重新导入 v3 规则文件。**

各分辨率对照表（换手机时用；表中数值一律按**竖屏**宽×高口径）：

| 分辨率 | x（起点=终点） | y1 起点（屏幕 75% 高度） | y2 终点（屏幕 45.8% 高度） |
|---|---|---|---|
| **1272×2800（一加 Ace5 至尊版，默认）** | **707** | **2100** | **1282** |
| 1080×2400（经典命令原生适配） | 600 | 1800 | 1100 |
| 720×1600 | 400 | 1200 | 733 |
| 1080×1920 | 600 | 1440 | 880 |
| 1440×3200 | 800 | 2400 | 1466 |

公式：`x = 屏宽 × 0.556`，`y1 = 屏高 × 0.75`，`y2 = 屏高 × 0.458`，时长 `120ms` 不要改。
（这是经典命令 `input swipe 600 1800 600 1100 200` 的比例适配版——轨迹照搬、时长收紧，见第五节。）
查看真实分辨率：`adb shell wm size`（Physical size 后面**小的那个数是宽**），或设置里看。

改法：编辑规则 → 点 Shell 命令动作 → 改数字。上滑 = 下一个；下滑（y1/y2 对调）= 上一个。

## 五、翻页问题的完整修复说明（v3 更新）

### v3：修复「命令成功但抖音不翻页」（x 坐标越界，2026-10-24）

v2 及更早的规则把一加 Ace 5 至尊版按「2800×1272（宽×高）」计算，得出 x=1556。但这台手机实际是 **1272×2800 竖屏**——屏宽只有 1272。x=1556 超出屏幕右边界，`input` 注入的触摸事件被系统静默丢弃，Shell 命令返回成功，抖音却收不到任何手势。

**v3 命令**：`input swipe 707 2100 707 1282 120`

| 参数 | v2（有 bug） | v3（修正后） | 说明 |
|---|---|---|---|
| x | 1556 ❌ 越界 | **707** | 55.6% × 屏宽 1272，落在屏幕内 |
| y1 起点 | 954 | **2100** | 75% × 屏高 2800 |
| y2 终点 | 583 | **1282** | 45.8% × 屏高 2800 |
| 时长 | 100ms | **120ms** | 818px/120ms ≈ 2424dp/s，远超 fling 门槛 |
| 竖屏口径 | 误用 2800×1272 | **1272×2800** | `wm size` 输出里**小的数是宽**；坐标现按竖屏口径写死在规则里，换手机按上表比例换算 |

### v2：修复「一跳一跳、时成时不成」（保留备查）

v2 之前的命令是 `input swipe 1400 990 1400 320 300`（300ms 滑 670px）。问题在于这个手势**踩在抖音翻页判定的边界线上**：

- 300ms 滑 670px ≈ 790dp/s，只比系统 fling（快滑）最低门槛高一点；
- 滑动距离只有屏高的 52.7%，刚过抖音 ViewPager 翻页距离阈值（通常 20%~50%）；
- 两个条件都卡在及格线边缘 → 有时判定成翻页，有时判定成慢拖（滑一半回去），表现就是"一跳一跳、时成时不成"。

**v2 起改成"坚决手势"**（轨迹比例照搬经典命令、时长收紧），v3 沿用同一套比例，只修正坐标口径与时长。

如果还有问题，按这个顺序排查：

1. **先单测命令**：电脑连手机 `adb shell su -c "input swipe 707 2100 707 1282 120"`，连续手动执行 10 次，应该 10/10 翻页。如果有失败的，换工作区 `douyin-swipe-test.sh` 里的 V1~V8 变体再试（V7=现役模仿版，V8=原命令直搬反例），把结果告诉我。
2. **还是连翻两页**（挥一次跳两个视频）：在规则「进阶选项 → 重复执行策略」里找「取消执行新任务，继续执行旧任务」或「最小执行间隔」，设 1 秒；没有该选项就用下面这个带文件锁的版本（自动互斥，连翻两页必消）：
   ```
   su -c "mkdir /data/local/tmp/dylock 2>/dev/null || exit 0; input swipe 707 2100 707 1282 120; sleep 0.8; rmdir /data/local/tmp/dylock"
   ```
   万一哪天完全失灵（连续挥多次都不翻页），是残留的锁目录导致，跑一次 `su -c "rm -rf /data/local/tmp/dylock"` 即可恢复。
3. **语音方案**：根本上解决重复触发问题的是改成语音口令——每次说一个字执行一次，自带 0.8 秒冷却，见《语音切抖音-使用指南.md》。语音版 App（v3.1 起）识别到口令后震动提示，翻页执行默认走「通知触发」（发魔法串通知，ShortX 收到即滑动），后台/洗碗湿手场景不受系统拦截影响。

## 六、排错 FAQ

| 现象 | 原因与解法 |
|---|---|
| 挥手没反应 | ① 看 root 是否授权给 ShortX；② 屏幕是否亮着；③ 手机是否立放、手是否真的扫过了**屏幕上方听筒旁**那个小点（距离传感器在那儿，不在屏幕中间）；④ 先手动验证坐标：电脑连手机跑 `adb shell su -c "input swipe 707 2100 707 1282 120"`，抖音能翻页说明命令没问题；⑤ 如果导入的是 v2 规则（命令里 x=1556），请重新导入 v3 规则——1556 超出屏宽会被系统丢弃 |
| 挥一次跳两个视频 | 一次挥动穿过了传感器边界两次（near→far→near）。挥慢一点：手掌遮住传感器停 300ms 以上再移开；或按第五节方法 2 设重复执行策略/文件锁 |
| 翻页一跳一跳、时成时不成 | 见第五节 v2 说明（已修复：更快 + 更长 + 静默） |
| 洗脸/做饭时误翻页 | 弯腰凑近看手机时脸/头发扫过传感器。给规则加条件「抖音有音频焦点」（只在抖音出声时响应），或把灵敏度调低 |
| 音量键规则一次跳两页 | ShortX 可能对按键按下和抬起都触发。只保留「下一个」方向即可接受；或改用摇一摇规则 |
| 音量键规则声音变小了 | 规则内已附带 `input keyevent 25` 还原音量；若仍漂移，在动作里再加一条 `su -c "input keyevent 25"` |
| 传感器贴了钢化膜不灵 | 厚钢化膜会挡红外。撕膜或把传感器窗口擦干净再试 |
| 免费版不能用 | ShortX 免费版只含基础功能，部分触发器/动作需高级版 |

## 七、关于「距离传感器」触发器的一条诚实说明

ShortX 官方文档只列出了部分触发器（应用/通知/音频/窗口等 10 类），没有完整清单；但官方共享规则库证明 **`AccelerometerSensor`（加速度传感器）触发器真实存在**，且 ShortX 宣传有 96 个触发器。按同款命名规范，距离传感器应为 `type.googleapis.com/ProximitySensor`，三个规则文件即按此生成。

**自检方法（10 秒）**：导入挥手规则 → 打开规则看触发器是否显示为「距离传感器」并可选靠近/遮挡。
- 显示正常 → 直接用；
- 显示为空/报错 → 用第三节的方法 C 手动搭一遍，搭完在规则菜单「分享 → 文件」导出，把导出内容发我，我按你机器上的真实类型名修正 JSON。

## 八、工作原理（想自己改的看）

```json
{
  "facts":      [{ "@type": ".../ProximitySensor" }],        // 触发器：距离传感器
  "conditions": [{ "@type": ".../ScreenIsOn" }],             // 条件：屏幕开着
  "actions": [
    { "@type": ".../ShellCommand",
      "command": "su -c \"input swipe 707 2100 707 1282 120 && sleep 0.8\"",  // root 注入上滑
      "singleShot": true },
    { "@type": ".../Vibrate", "vib1": 80 }                    // 震动确认
  ]
}
###------###
{"type":"rule"}
```

`input swipe` 是安卓系统自带命令，经 root 从系统框架层注入完整触摸序列（按下→移动→抬起），抖音拿到的信号与真人手指完全一致，无法分辨。
