# 手势切抖音 · 使用指南（v5.3 · 8 种表情动作）
> 注：本文里的 APK 文件名 `手势切抖音-vX.Y.apk` 指发布版；如果你是从源码构建，
> 产物在 `build/gesture-douyin-vX.Y.apk`，功能完全一致。


> 对着手机前置摄像头**比个手势**或**做个表情**，抖音自动翻到下一个 / 上一个视频。
> 完整离线、不联网、**不使用麦克风**、不使用 root。识别只负责判断动作，真正的滑动仍由 ShortX 规则执行。

---

## 一、这一版是什么

| 项目 | 说明 |
|---|---|
| 识别方式 | 前置摄像头（MediaPipe 视觉模型），**无语音、无麦克风** |
| 手势模式 | **数手指数**：伸 1/2/3/4/5 根手指，哪一种算「下一个」由你自己定（阈值可调） |
| 表情模式 | **8 种动作**（张嘴/露牙笑/龇牙/撅嘴/鼓腮/抬眉/眯眼/睁大眼），两个方向任选 |
| 响应速度 | 约 0.4~0.8 秒（手势 7fps 保持 0.4 秒 / 表情 5fps 保持 0.5 秒） |
| 耗电 | 约 1W，洗 40 分钟碗约 5~8% 电 |
| 安装包 | 约 25MB（v4.5 模型改为压缩存放，比上版小 2.5MB） |
| 系统要求 | Android 8+，**必须 64 位（arm64）**；需摄像头权限 |
| 高精度模式 | 可选，960×720 采集（默认关，识别更准但更耗电） |
| 摄像头预览 | 可选，在 App 内看引擎实际看到的画面（调角度用） |
| 画面放大 | 滑条 1.0x~4.0x，离得远就调大（视野变窄、超过 3x 会明显变糊） |
| 息屏行为 | **息屏即停止识别**（等同手动停止，亮屏需重新开启） |

**与旧语音版的关系**：v4.0 是独立功能，已删除全部语音代码。旧语音版（v3.9）仍可正常使用，两个 APK 不能同时安装（同包名）。

## 二、安装与首次设置（约 3 分钟）

1. 安装 `手势切抖音-v5.3.apk`（覆盖安装旧版会保留 ShortX 配置）
2. 打开 App → 点「授予摄像头权限（必须）」→ 选「仅在使用中允许」
3. 点「授予「使用情况访问」权限」→ 在列表里找到本 App 并允许（用于「只在抖音前台时响应」，可选但建议）
4. **ShortX 侧**：确认已导入「DeepLink 动作」规则（`ShortX-抖音挥手切换-使用指南.md` 里有两个动作的建法），规则开关打开、ShortX 在 LSPosed 中启用
5. 回到本 App，把两条 `shortx://run?id=DA-xxxx` 链接粘到「DeepLink 链接」两个输入框里（「下一个」「上一个」各一条）
6. 点「测试「下一个」」→ 抖音应翻页。这一步通了，说明执行链路 OK，剩下只是识别问题

## 三、识别方式（二选一）

### 手势模式（数手指，v4.3 全新）

**不再依赖「比耶」这类内置手势分类**（那个对角度和光线太挑，实测很难稳定认出来）。
现在直接数你伸出了几根手指：

| 伸几根 | 怎么摆 | 默认效果 |
|---|---|---|
| 1 根 | 只伸食指 | 下一个 |
| 2 根 | 食指 + 中指（V 字） | 上一个 |
| 3 / 4 / 5 根 | 依次多伸一根 | 未分配，可在 App 里自选 |

"下一个"和"上一个"分别用几根手指，**在首页「手势动作」区自己选**（两个不能选同一个）。
保持 **0.4 秒**触发；中途短暂丢失 450ms 内不会清零重新计时。

**握拳（0 根）不触发**——洗碗时握碗、攥抹布都是握拳，正好天然避开。

**手怎么摆**（比手势识别宽容很多，但仍需手在画面里）：

1. **手抬到脸旁**——不要放在胸前或画面下缘，前置摄像头只看得到脸周围那一块
2. **掌心朝镜头**，手指伸直张开（指尖不要叠在一起）
3. **离镜头 30~60cm**，手占画面 1/4 高度左右

> 日志里会实时写「手势诊断：2 根手指（拇✗ 食✓ 中✓ 无✗ 小✗），保持 400ms 即触发」，
> 连哪根手指被判成伸出/收起都会列出来——数错了就照着调姿势。

### 表情模式（默认）

v5.3 起可选 **8 种动作**，「下一个」和「上一个」各自任选（不能相同）：

| 动作 | 做法 | 推荐阈值 | 说明 |
|---|---|---|---|
| **张嘴** | 嘴张开（保持 0.5 秒） | 0.55 | 最稳，默认「下一个」 |
| **露牙笑** | 咧嘴笑、露出牙齿 | 0.45 | 嘴角上扬的程度 |
| **龇牙** | 上下唇分开、上下牙都露出来 | 0.30 | 上唇上提 + 下唇下拉，比「张嘴」更强调露齿 |
| **撅嘴** | 嘴唇向前嘟起 | 0.50 | 默认「上一个」 |
| **鼓腮** | 腮帮子鼓起来 | 0.40 | 洗碗时不会做，抗误触好 |
| **抬眉** | 眉毛上挑 | 0.55 | |
| **眯眼** | 眼睛眯成一条缝 | 0.45 | |
| **睁大眼** | 眼睛睁大（惊讶状） | 0.45 | |

- 默认：张嘴 → 下一个，撅嘴 → 上一个
- 换动作时右侧**阈值会自动填成该动作的推荐值**（不同动作的分数分布差很多，沿用旧阈值往往不好用）
- 两个方向不能选同一个动作（App 会自动拦下并提示）

> 「露牙」有两种做法，看你要哪种：**露牙笑**（咧嘴笑，检测嘴角上扬）比 **龇牙**（上下唇分开露齿）
> 更容易触发；如果只是想让口腔动作别和「张嘴」重复，选「龇牙」区分度更大。

> 为什么不用「眨眼」：人自然眨眼每分钟 15~20 次，会疯狂误触发。
> 为什么手势不用「握拳/张开手掌」：洗碗时握碗、冲碗就是这两个动作。

**准确率做了四层优化**：① 分数非对称平滑（上升快、下降慢，动作一起来就能判、抖动又不会
打断）；② 启动后先花约 2 秒学习你的「中性表情」基线；③ 阈值随基线自适应，但**最多只比
你设的阈值高 0.10**（所以你把阈值调低是真的会更灵敏）；④ 日志实时写
「表情诊断：张嘴 0.42/0.55，撅嘴 0.08/0.50」——斜杠左边是实时分数，右边是当前阈值。

## 三之一、高精度模式（v4.6）

**位置**：首页「识别方式」下方，「高精度模式（960×720 采集…）」开关。默认关闭，改完需「停止识别」再「开启识别」。

| | 标准（默认） | 高精度 |
|---|---|---|
| 采集分辨率 | 640×480 | **960×720**（像素量 2.2 倍） |
| 适合 | 光线好、手在 30~60cm | 手离得远、手指细节小、光线偏暗 |
| 代价 | — | CPU 与耗电上升，帧率可能略降 |

**怎么确认生效**：开启后日志第一行会写「采集分辨率 960×720（高精度模式），识别模型已就绪」，
状态区也会显示「采集：高精度 960×720」。如果你看到的是 1280×720 或 640×480，
说明手机前置摄像头不支持 960×720，App 自动选了最接近的尺寸——同样能用。

> 说明：这个选项在 v4.1 的对话里只是我提的一个「备选方案」，当时并没有实现，所以之前的版本里
> 找不到它。v4.6 才真正做出来。

## 三之零、画面放大（v5.1）

**位置**：首页「高精度模式」下面的**滑条「画面放大」**，范围 1.0x ~ 4.0x，拖动即时生效（不用重开识别）。

**为什么有用**：手机离你远时，脸和手在 640×480 的画面里只占很小一块，识别模型要把整幅图缩小后
才处理，细节就丢了。放大相当于**只把画面中心那块送去识别**，人和手在模型的输入里更大，
检测率和关键点精度都会明显提升。

| 倍率 | 视野 | 适合 |
|---|---|---|
| 1.0x | 全部画面 | 手机离得近（<50cm） |
| **1.5~2.0x（推荐）** | 中心 44%~25% 面积 | 洗碗时手机在台面上、离你 60~100cm |
| 3.0x | 中心 11% 面积 | 手/脸在画面里很小 |
| 4.0x | 中心 6% 面积 | 极限情况：手机放得很远/很低；画面明显变糊，优先考虑挪近手机 |

**注意**：放大后**视野会变窄**，手/脸要保持在画面中间，出框就检测不到。配合「摄像头预览」调：
一边拖滑条一边看预览框，把人脸和手放到合适大小即可。

状态区会显示当前倍率（如「采集：标准 640×480 · 放大 1.5x」）。

## 三之二、阈值怎么调（v4.3）

动作选项右边那个小输入框就是阈值，两行各一个，改完自动保存。

### 表情阈值（张嘴 / 撅嘴，默认 0.55 / 0.50）

含义：**动作分数要超过多少才算数**（0~1）。

| 现象 | 怎么改 |
|---|---|
| 做了动作但日志分数只到 0.4，不触发 | **调低**，每次 0.05，比如 0.55 → 0.45 |
| 没做动作也偶尔触发（比如说话时下巴动） | **调高**，比如 0.55 → 0.65 |

判断依据就是日志那行：「张嘴 0.42/0.55」表示你张嘴时分数只到 0.42，比门槛 0.55 差一点，
把阈值调到 0.40 就能触发。**改完立即生效，不用重开识别。**

> v4.4 修正：**你设多少就是多少**。之前 App 会把「启动时学到的中性表情基线 + 0.22」当作
> 阈值下限，你填 0.2 实际仍按 0.28 判（日志里显示的就是这个被抬高的值），看起来像「调了没用」。
> 现在基线只在日志里显示（`（基线 0.06）`）供参考，不再参与判定。

### 手势阈值（默认 0.35）

手势是数手指，没有「分数」概念，所以这个阈值是**手部检测置信度**：越高越严格。

| 现象 | 怎么改 |
|---|---|
| 日志一直说「画面里没有手」 | **调低**到 0.25 甚至 0.20（手离得远、光线弱时更容易检测到） |
| 背景里有手形物体也乱触发 | **调高**到 0.5 |

> 手势阈值改了**必须「停止识别」再「开启识别」**才生效（它决定了模型的初始化参数），
> 表情阈值不需要。

## 四、怎么摆手机

- 手机**斜靠台面、屏幕朝向自己**，前置摄像头能拍到你的脸和手
- 距离 40~80cm 最合适；太远（>1.5m）检测率下降
- 光线：白天自然光最好；晚上避免背后强光（逆光）和顶灯直射（脸上过曝）
- 状态栏会亮**摄像头绿点**：这是 Android 12+ 的系统提示，无法隐藏，属于正常现象

### 用「摄像头预览」调位置（v4.7）

首页往下拉到「摄像头预览」区，打开「显示摄像头画面」：黑框里就是**识别引擎实际看到的那一帧**，
每 0.2 秒刷新一次（识别照常工作，不会抢摄像头）。

- 画面是**竖屏正立**方向、**未做镜像**（就是摄像头真实所见，不是自拍预览的镜像效果）
- 需要先「开启识别」才有画面；没启动时会提示
- 用法：把手抬到画面里 → 看手占多大、光线够不够 → 按这个位置固定手机
- 结束时关掉开关即可；退出 App 会自动停止预览，不会在后台占资源

**画面方向不对怎么办**：预览框下方有一行「画面方向：自动」+ 按钮「画面方向 +90°」。
点一下就在当前画面上再转 90°，点几次调到正立为止（设置会记住）；长按按钮恢复自动。
各厂商对前置摄像头方向的定义不一致，v4.8 已按你机型的实测情况把自动值修正过，
如果仍有偏差，用这个按钮现场调即可。

## 五、重要设置

**触发冷却（秒）**：两次翻页之间的最短间隔，默认 1.5 秒。想更快连翻就调小（如 0.8），想防误触就调大（如 3）。

**执行通道（v4.4 起只剩 DeepLink）**：App 拉起 `shortx://run?id=...`，由 ShortX 规则执行滑动。

- 需要：ShortX 已装并在 LSPosed 启用 + 本 App 有「后台弹出界面」或「悬浮窗」权限
- 首页**两个输入框**要粘贴链接（「下一个」「上一个」各一条，形如 `shortx://run?id=DA-xxxx`）
- ShortX 重新导入规则后 id 会变，记得同步更新
- 没填链接时通道状态会显示「⚠ 上方链接还没填」；只填了「下一个」会提示只能翻一个方向
- v4.4 已删除「通知触发」通道（不再需要 ShortX 的通知类规则，也不再发 HF_CMD 通知）

**反馈（v4.5 只剩震动）**：识别到动作两短震、拉起 ShortX 单击、失败长震。
提示音与语音播报已删除（不用再调音量，也不会和抖音声音打架）。

**不再有「运行设置」**：v4.5 已删除这三项，行为固定为

- 不做开机自启（重启手机后需手动打开 App 再点「开启识别」）
- **息屏 = 手动停止识别**：屏幕一熄灭，服务立即结束、相机关闭、通知消失，
  跟手动点「停止识别」完全一样；**亮屏后也不会自动恢复**，需要回 App 重新点「开启识别」
- 触发不再判断「当前是不是抖音」——任何界面下做动作都会拉起 ShortX 规则
  （原「只在抖音前台时响应」已删除）。想让别的 App 不被误切，把冷却调大、或换更不容易误做的动作

## 六、排错

| 现象 | 原因与解法 |
|---|---|
| 状态显示「⚠ 未授权」，引擎未启动 | 点「授予摄像头权限」，选「仅在使用中允许」，再点「开启识别」 |
| 提示「模型加载失败」 | 20 秒内模型没加载完会自动停服。重启 App 再开；反复失败请反馈日志 |
| 提示「相机打开失败」 | 摄像头被其他 App 占用（视频通话、相机没退），关掉再试 |
| 离得远识别不到 | 把「画面放大」调到 1.5x~2.0x（配合摄像头预览确认人和手在中心）；仍不行可再开「高精度模式」 |
| 手势一直不触发 | **先看日志里的「手势诊断」**：①「画面里没有手」→ 手抬到脸旁、掌心朝镜头、30~60cm，或把手势阈值调低；②「数到 3 根手指」但你只伸了 2 根 → 看括号里哪根判错（拇✗ 食✓…），调整姿势（常见是拇指被多数进去）；③「保持 400ms 即触发」但没翻 → 是执行链路问题，不是识别 |
| 表情一直不触发 | 看「表情诊断」的分数：分数接近阈值 → **把阈值调低**（见三之二）；分数很低（<0.2）说明脸不在画面里或光线太暗。日志出现「表情校准完成」之前（约 2 秒）不会触发，属正常 |
| 识别到了但抖音不动 | 执行链路问题：看日志有没有「已拉起 ShortX DeepLink」；没拉起说明 ShortX 未启用/缺权限，拉起了但没翻说明 ShortX 规则本身有问题。先用「测试「下一个」」按钮定位 |
| 频繁误触发 | 换更「不自然」的动作组合（比如「撅嘴 → 下一个，张嘴 → 上一个」）；把冷却调到 2~3 秒 |
| 一开就停 | 检查是否被系统省电策略杀后台：设置 → 电池 → 本 App → 不限制 |
| 息屏后不识别了 | **这是设计行为**（v5.0）：息屏等于手动停止，亮屏后需回 App 重新点「开启识别」。如果希望息屏也继续识别，告诉我改回去 |
| 打开预览但黑屏 | ① 识别没开：先点「开启识别」；② 手机在息屏/后台：回到 App 亮屏；③ 刚开启识别时需等模型加载 1~3 秒 |
| 预览画面方向不对（上下颠倒等） | 点预览框下方「画面方向 +90°」按钮，每点一次转 90°，调到正立为止（会记住）；长按恢复自动 |
| 32 位老手机 | 本版只含 arm64 库，32 位设备无法使用视觉引擎 |

## 七、原理与隐私

- 所有识别在手机本地完成（MediaPipe + TFLite 模型），**不联网、不上传任何图像**
- 摄像头画面只在内存中处理（每 150~200ms 取一帧、转成 640×480 位图后立即复用，不写文件）
- 不需要麦克风、不需要 root、不需要无障碍服务、不读取使用记录
- 滑动由 ShortX 规则执行（`input swipe`），本 App 只负责拉起一条 `shortx://` 链接
